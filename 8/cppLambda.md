# 9/10 — Lambda

### Lambda란 무엇인가?

익명 함수를 그 자리에서 사용할 수 있게 해주는 것

### Lambda는 왜 필요한가?

가독성과 코드의 응집도를 위하여.

함수 포인터나 함수 객체를 위해 외부에서 클래스나 함수를 따로 선언하지 않아도된다.

### Lambda의 기본 문법은 어떻게 생겼는가?

[capture](parameters) -> return_type { body }

auto add = [](int a, int b) -> int { return a + b; };

### Lambda에서 capture란 무엇인가?

함수 외부의 변수들을 내부로 가져와 사용할 수 있게 하는 것

### 값 캡처와 참조 캡처의 차이는?

값 캡처 - 복사하여 캡처 (값전달과 유사)

참조 캡처 - 참조하여 캡처 (참조전달과 유사)

### Lambda와 함수 객체의 관계는?

내부적으로 컴파일러는 람다 표현식을 만나면 operator()가 오버로딩된 이름 없는 클래스를 자동으로 생성한다.

즉, 람다는 컴파일러가 만들어낸 함수 객체다.

### Lambda는 STL에서 어떻게 활용되는가?

함수들에 사용자 정의 조건을 전달할 때 주로 활용된다.

ex) sort(v.begin(), v.end(), [](int a, int b) -> bool {return a > b})

### 서버 코드에서 Lambda를 사용할 만한 상황은?

(gemini 인용)

서버 코드에서 람다(Lambda)를 활용하기 좋은 대표적인 상황은 다음과 같습니다.

1. 비동기 I/O 콜백 (Asynchronous Callbacks)

- 네트워크 소켓의 읽기/쓰기 대기, DB 쿼리 요청 등 비동기 작업이 완료되었을 때 실행할 로직을 정의할 때 사용합니다. (예:
  Boost.Asio의 이벤트 핸들러)
- 콜백 함수를 따로 분리할 필요 없이, 요청을 보내는 코드 바로 아래에 실행 로직을 작성할 수 있어 가독성과 응집도가 높아집니다.
- 캡처(Capture)를 통해 현재 세션이나 패킷 정보를 콜백 내부로 쉽게 전달할 수 있습니다.

2. 스레드 풀 및 작업 큐 (Thread Pool & Task Queue)

- 백그라운드 스레드에서 처리해야 할 무거운 작업(Task)을 정의하여 큐에 삽입할 때 사용합니다.
- 기존의 std::bind나 함수 객체(Functor)를 래핑하는 대신, 람다를 사용하여 std::function<void()> 형태로
  컨텍스트와 실행 코드를 간단하게 묶어서 전달할 수 있습니다.

3. 타이머 이벤트 (Timer Events)

- "N초 뒤에 특정 유저의 버프 해제", "재접속 대기 시간 만료 처리" 등 일정 시간 후 지연 실행되어야 하는 로직을 타이머 시스템에
  등록할 때 유용합니다.

4. 리소스 관리 및 커스텀 삭제자 (Custom Deleters)

- 메모리 풀(Memory Pool)을 사용하는 서버 환경에서, std::unique_ptr이나 std::shared_ptr이 소멸할 때
  단순히 delete를 하는 대신 "메모리 풀로 객체 반환" 또는 "소켓 닫기" 등의 특정 로직을 수행하도록 람다를 커스텀 삭제자로 지정할
  수 있습니다.

5. 임계 구역(Critical Section) 캡슐화

- 멀티스레드 환경에서 뮤텍스(Mutex) 락을 잡고 수행해야 하는 데이터 갱신 로직을 람다로 감싸면, 락이 유지되는 스코프를 최소화하고
  명확하게 관리할 수 있습니다.

6. STL 알고리즘 활용

- 접속 중인 유저 목록에서 특정 조건을 만족하는 세션을 찾거나(std::find_if), 리더보드를 정렬(std::sort)할 때 필요한
  조건식(Predicate)을 별도의 함수 선언 없이 즉석에서 작성할 때 사용합니다.
